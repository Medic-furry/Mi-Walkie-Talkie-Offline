# 小米对讲离线（Mi-Walkie-Talkie-Offline）

一个完全离线、无需登录的 Android BLE 工具，用于连接小米对讲机，管理频道和设备参数，并进行固件升级。

项目使用 Kotlin 重写，不依赖小米账号或官方服务器即可进行本地设备操作。

**当前开发重点：小米对讲机 2（Shark）及 `1.0.5+M1` 修改固件。**

GitHub：[Medic-furry/Mi-Walkie-Talkie-Offline](https://github.com/Medic-furry/Mi-Walkie-Talkie-Offline)

---

## 项目说明

原版小米对讲机 App 的部分功能依赖在线账号和服务器。随着旧版登录认证逐渐失效，即使设备本身和蓝牙通信正常，也可能无法正常使用部分功能。

这个项目最初参考了 Darkhorse 的开源项目 [Mi-Walkie-Talkie-Plus](https://github.com/Mi-Walkie-Talkie-by-Darkhorse/Mi-Walkie-Talkie-Plus)（分支 `2.13.7-plus`）。之后，我使用 Kotlin 重新编写了 Android 端实现，去掉登录相关流程，保留设备通信和固件升级功能。

开发过程中参考了官方 App 的部分实现，并结合 BLE 抓包、代码分析和固件逆向，逐步还原设备通信协议。

目前不同机型的适配程度并不相同：部分功能已经通过真机测试，另有一些机型和协议分支目前只完成代码适配，尚待实际设备验证。

## 项目特点

- 无需登录小米账号。
- 无需连接官方服务器即可进行本地 BLE 操作。
- 读取和修改设备频道。
- 修改设备参数。
- 频道排序、拖拽和批量整理。
- 支持固件文件识别及设备固件升级。
- 支持中英文界面。
- 针对小米对讲机 2 的 `1.0.5+M1` 修改固件提供额外功能。
- 不需要修改或卸载官方 App，可以与官方 App 共存安装。

## 支持机型

目前主要适配小米对讲机 2 及更早的机型。不同型号使用的 BLE 服务和通信协议并不完全相同，因此并不是所有机型都具备相同的功能。

| 机型 | 代号 | BLE GATT 服务 | 设备类型 | 当前状态 |
|---|---|---|---|---|
| 小米对讲机 2 | Shark | `0000fdab-...` | `4` | 已适配，主要功能已通过真机测试 |
| 小米对讲机 1S | Seal | `0000aee7-...` | `5` | 代码已适配，尚未真机验证 |
| 小米对讲机 1S（部分新固件批次） | Seal | `0000fdab-...` | `5` | 已增加握手识别修复，尚未真机验证 |
| 小米对讲机 1 代 | Dolphin | `0000fee7-...` | `1` | 可识别并发起握手，频道及参数协议尚未适配 |
| 小米对讲机 Lite | Lite | `0000aec7-...` | `36611` | 可识别，通信及刷写功能尚未移植 |

### 机型说明

**小米对讲机 2（Shark）**

目前主要开发和测试机型。

- BLE 连接及握手。
- 频道读取、修改和保存。
- 设备参数读取和修改。
- 固件升级。
- `1.0.5+M1` 修改固件扩展功能。

固件文件命名遵循：

`shark_*_hw<N>.bin`

**小米对讲机 1S（Seal）**

已根据官方代码适配 Seal 机型的设备类型和升级状态机。

部分新固件批次的 1S 只暴露 `fdab` 服务，不能单纯根据 GATT 服务判断为 Shark。针对这个问题，V1.0.2 增加了握手响应识别和自动纠正逻辑。

需要说明的是，目前没有 1S 真机用于验证，因此这里的代码适配不代表已经完成设备实测。

固件文件命名遵循：

`seal_*_hw<N>.bin`

**小米对讲机 1 代（Dolphin）**

目前可以识别设备并发起握手，但频道和设备参数所使用的遗留 MITALK 协议尚未完成适配。

固件文件识别：

`mcu_ble_*.bin`

1 代使用的固件传输流程与 Shark / Seal 不同，目前尚未移植对应的完整传输逻辑。

**小米对讲机 Lite**

Lite 使用独立的协议实现，包括 `LiteProtos` 和自定义 BLE 传输层。

目前只能识别机型，尚不能正常进行设备功能操作或固件刷写。

官方 Lite 固件更新流程涉及服务器下发固件信息，再通过 BLE 传输固件。相关 `FirmwareInfo{MD5,localPath}` 和 `lite/e` 传输层尚未移植，需要 Lite 真机进行后续验证。

**暂不支持**

- 小米对讲机 2S。
- 小米公网对讲机。
- 小米对讲机 3 代及更新机型。

### 设备识别

目前根据 BLE GATT 服务及握手响应识别设备。

官方设备类型枚举：

| 设备类型 | 数值 |
|---|---:|
| Dolphin | `1` |
| Shark | `4` |
| Seal | `5` |
| Lite | `36611` |

部分新固件设备可能使用与其他机型相同的 GATT 服务，因此不能只依赖服务 UUID 判断机型。

如果需要增加其他机型，需要抓取设备 GATT 服务表及握手响应，具体流程见 [DEVELOPMENT.md](DEVELOPMENT.md) 第 13 节。

## 功能说明

### 频道管理

- 读取设备频道列表。
- 添加和编辑频道。
- 删除频道。
- 修改频道参数。
- 频道排序。
- 拖拽调整频道位置。
- 批量整理频道。
- 支持成组拖拽。

频道数量和可用槽位由设备固件决定，App 不会仅根据界面上的输入范围判断设备是否能够保存。

### 设备参数

根据设备及固件实际支持的协议字段，提供相应的参数读取和修改功能。

不同机型的参数支持情况可能不同。部分参数虽然可以通过协议发送，但是否能够在设备端生效，还需要对应机型的实际测试。

### 固件升级

支持识别不同机型对应的固件文件，并根据机型选择相应的升级流程。

目前主要完成 Shark 的固件升级流程。Seal 已移植对应升级状态机，但尚未进行 1S 真机验证。

Dolphin 和 Lite 的固件文件可以进行部分识别，但其传输协议尚未完成移植，不能据此认为已经支持刷机。

**刷写固件前，请确认固件型号、硬件版本和设备型号一致。**

## `1.0.5+M1` 修改固件

`1.0.5+M1` 是针对小米对讲机 2（Shark）开发的修改固件。App 中部分扩展功能需要设备运行对应版本的修改固件才能使用。

以下功能主要针对 `1.0.5+M1` 开发和测试。

### 1. 自定义频道数量

官方原版固件的频道读取流程在 20 个频道处存在截断。

修改固件扩展了频道容量，App 也针对原有读取流程增加了补充探测：

- 频道数量由 20 个扩展至 29 个。
- 官方读取链路完成后，继续探测第 21 至第 29 个频道。
- 已通过真机测试，29 个频道均能完整同步。
- 实际可用容量仍由设备固件裁决，超出设备容量时会拒绝保存并提示失败。

槽位选择范围由 App 自动判定：连接后 App 发一次 `0x4E29 chType=3` 指纹探测——
1.0.5+M1 回记录（FM 数据区）判为修改固件，容量按 29 封顶；官方固件回 EMPTY，容量按 20。
选择器、读取探针、整理视图全部按判定的容量封顶，不再使用固定 1～200。

### 2. FRS 频道

在预设频道页面增加第三组宫格，用于显示修改固件内置的 FRS 频道。

相关实现：

- 使用固件内置的 22 个频道固定表。
- 频道频率数据来自固件内置表，相关数据位于 `0x319DC`。
- 点击频道后，通过 `0x4E27` 命令并使用 `type=9` 进行跳台。
- 频道名称与对讲机内部一致：中文 = 固件标签"北美家用频道"（`0x349F1`）+ 空格 + 序号
  （`0x4E28` 回显实测"北美家用频道 22"）；英文跟随固件英文串"FRS Channels"（`0x33C3C`）
  → "FRS Channels N"。

FRS 频道没有直接沿用普通 BLE 频道列表读取流程。

测试过程中发现：

- `0x4E29` 使用 `chType=3` 查询时，会读到 NVM 中残留的自定义频道数据。
- 分页游标不会正常前进。
- `chType=9` 查询没有响应。
- `0x4E28` 返回的频道记录空间中，FRS 对应 `type=9`。

因此，App 使用本地固定表显示 FRS 频道，再通过跳台命令让设备切换频道，而不是尝试从普通 BLE 频道列表读取。

### 3. 0.5W 发射功率

增加 0.5W 功率档位。

- 对应参数：`chTxPower=3`。
- 如果官方原版固件不接受该参数，App 会提示修改失败，并重新读取设备参数，保持设备实际返回的功率档位。

### 4. 扫描模式

增加扫描模式入口。

相关命令：

- 进入扫描：`0x4E27`，`deviceMode=3/4`。
- 退出扫描：`0x4E27`，`deviceMode=0`。
- 扫描期间每秒轮询一次 `0x4E26`，读取设备返回的扫描状态。

扫描功能需要固件侧支持对应的工作模式。

### 5. 每频道静噪和 VOX 参数

增加每个频道的以下参数透传：

| 参数 | 协议字段 |
|---|---|
| 静噪（SQ） | `field7` |
| VOX | `field8` |

编辑频道时，App 会将对应字段原样发送。

目前已完成字段透传，但参数在设备端的实际生效情况仍需要进一步验证。

需要注意，设备面板中的「静噪等级」是全局设置，与这里的每频道静噪字段不是同一个参数。BLE 协议中没有找到对应的全局静噪等级字段，因此目前只能通过设备面板设置。

### 官方原版固件的行为

上述扩展功能主要针对 `1.0.5+M1` 修改固件开发。

使用官方原版固件时，App 会按照设备实际支持的功能进行操作。部分修改固件专属功能无法使用，不会强行写入设备不支持的参数。

## 编译

项目使用 Android Studio 和 Gradle 构建。

1. 克隆仓库：

   ```bash
   git clone https://github.com/Medic-furry/Mi-Walkie-Talkie-Offline.git
   ```

2. 使用 Android Studio 打开项目。
3. 等待 Gradle 同步完成。
4. 连接 Android 设备或启动模拟器。
5. 执行 `assembleDebug` 构建 APK。

项目需要 Android SDK 和对应的 Gradle 构建环境。

## 更新日志

### V1.0.2（2026-11-04）

#### 1S 设备识别与握手修复

修复部分小米对讲机 1S 新固件批次的握手识别问题。

这类设备只暴露 `fdab` 服务，原先会被误判为 Shark（`deviceType=4`）。设备拒绝握手后，会在响应的 `field4` 中返回实际设备类型 `5`（Seal）。

现在的处理流程：

- 首次握手被拒绝后，读取设备返回的实际 `deviceType`。
- 根据返回值自动纠正机型并重新握手。
- 按设备 MAC 地址记录学习结果。
- 下次连接时优先使用已学习的设备类型。

Android 14 及更新版本可能协商出 `MTU=517`，这是 Android 系统的行为。当前帧收发不依赖该 MTU 值，因此没有针对这个数值增加特殊处理。

注意：这部分属于代码适配，目前尚未使用 1S 真机验证。

#### `1.0.5+M1` 固件功能

本版本主要针对 `1.0.5+M1` 修改固件。

- **频道数量扩展：** 支持读取和同步 29 个频道。官方读取链路在 20 个频道处截断后，App 会继续探测第 21～29 个频道。已通过真机测试，29/29 全部同步。
- **FRS 频道：** 增加预设频道页面第三组宫格，使用固件内置的 22 个频道固定表显示，并通过 `0x4E27` 命令跳转。
- **0.5W 功率：** 增加 `chTxPower=3` 功率档位。
- **扫描模式：** 增加扫描模式入口、模式切换及状态轮询。
- **SQ / VOX：** 增加每频道静噪和 VOX 字段透传。

#### 频道拖拽修复

修复修改固件下，拖动 29 号等前方存在空槽的频道时，展开槽位列表后拖拽立即取消的问题。

原因是展开槽位列表时会插入大量占位行，目标位置可能因此被推到屏幕外，导致无法获取对应的 `ViewHolder`。

现在展开列表后会先自动滚动到目标位置，再获取 `ViewHolder` 并启动拖拽。拖拽跟踪由 RecyclerView 层处理，不再依赖最初按住的视图。

#### 频道号修改失败修复

修复编辑频道修改频道号时保存失败的问题。

原因是设备禁止删除"当前激活中"的频道（删除时返回 `FORBIDE`），而被修改的频道往往正处于激活状态。编辑页在删除前会自动切换到替身频道，迁移（删除 + 新建）完成后再把重编号的新频道切回激活。

#### 频道号选择改版

频道号选择从下拉框改为与预设频道同款的五列宫格弹窗：占用槽灰显不可选，空闲槽直接点选，当前槽高亮。

#### 多机型识别与固件升级适配

扩展机型识别范围：

- Dolphin：`deviceType=1`
- Shark：`deviceType=4`
- Seal：`deviceType=5`
- Lite：`deviceType=36611`

根据官方 `BaseUpdateActivity` 的分支逻辑，增加不同机型的固件文件识别：

- Shark：`shark_*_hw<N>.bin`
- Seal：`seal_*_hw<N>.bin`
- Dolphin：`mcu_ble_*.bin`

Seal 适配了与 Shark 共用的官方升级状态机，涉及 `0x4E2C`、`0x4E2D`、`0x4E2E` 等命令。目前属于代码移植和适配，尚未进行 1S 真机刷写验证。

Dolphin 和 Lite 已增加相应的机型及固件识别逻辑，但传输层尚未完成：

- Dolphin 使用遗留 MITALK 裸数据传输分支。
- Lite 使用独立的 `LiteProtos` 和自定义传输层，涉及官方服务器下发固件信息及 BLE 传输。

2S、公网对讲机暂不支持。

#### 文档

新增 `docs/握手协议_三协议族.md`，整理以下协议结构：

- Seal / Shark：`0x4E21` 帧。
- Dolphin：MITALK 帧。
- Lite：`blelib` cmdId 封装。

文档中同时标注了尚待真机核对的内容。
